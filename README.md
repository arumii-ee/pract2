# project-analyzer

프로젝트 폴더를 분석해 코드 구조를 정리하는 스크립트입니다. **C / Lua / Python**에 맞춰져 있고,
**Xilinx/AMD Vitis Classic 워크스페이스**(2019.2~2023.1, 2020.2 포함)를 인식합니다. Python 3.9+ 표준 라이브러리만 사용합니다.

## 사용법

```bash
python analyze.py <경로>                          # 터미널 요약
python analyze.py <경로> -f md -o STRUCTURE.md    # 상세 리포트 한 파일 (한눈에 보기·구조·함수 상세)
python analyze.py <경로> -f md -o report          # 폴더로 나눠 저장: report/index.md + report/files/<번호>_<진입점>.md
python analyze.py <경로> -f md -o report --lib miniz.c,miniz.h,Lib   # 외부 라이브러리 지정
```

| 옵션 | 설명 |
|---|---|
| `-f text\|md` | 출력 형식 (기본 text) |
| `-o 경로` | 결과 저장. md 형식에서 확장자 없는 경로(폴더)면 `index.md` + 진입점/스레드별 함수 상세로 분할 |
| `--lib a,b` | 외부(서드파티) 라이브러리로 취급할 파일/폴더 이름 또는 경로(와일드카드 가능). 통계·상세·진입점에서 빼고 호출 대상 해석에만 사용 |
| `--no-auto-lib` | 외부 라이브러리 자동 감지를 끔. 기본은 `Lib/`·`lib/`·`third_party/`·`vendor/`·`external/`·`deps/` 폴더와 `miniz.c`·`cJSON.c`·`sqlite3.c`·`stb_*.h` 같은 알려진 파일을 외부 라이브러리로 분류 (개요에 목록·이유 표시) |
| `--source-lines N` | md 리포트에 넣을 함수 소스 최대 줄 수 (기본 80, `0`=전체). 넘는 부분은 `… 이하 N줄 생략 (파일:시작-끝)` 표시 |
| `--max-size MB` | 이보다 큰 파일은 건너뜀 (기본 1). 건너뛴 파일은 이름·크기·이유를 리포트에 표시 |
| `-d N` | 디렉터리 트리 깊이 제한 |
| `-e a,b` | 추가로 제외할 폴더/파일 이름 |
| `--no-source` | md 리포트에 함수 소스 코드 생략 |
| `--include-generated` | Vitis BSP/FSBL 자동 생성 코드도 사용자 코드처럼 분석 |
| `--no-gitignore` | `.gitignore` 규칙을 무시하고 모든 폴더 탐색 |
| `--follow-links` | 심볼릭 링크/정션 폴더도 탐색 |

하위 폴더는 깊이 제한 없이 모두 탐색합니다. `.gitignore`는 git과 같은 규칙으로 적용합니다
(`/` 로 시작·중간에 `/` 가 있는 패턴은 해당 `.gitignore` 위치 기준, `**`, `!` 부정, 하위 폴더의 `.gitignore`).
무엇이 왜 제외됐는지는 리포트 개요의 **제외된 항목**에 규칙(파일:줄)과 함께 표시되며,
소스 코드가 하나도 잡히지 않으면 `--no-gitignore` / `--follow-links` 재실행을 안내합니다.

Vitis는 **워크스페이스 폴더 전체**를 넘기는 것을 권장합니다. 그래야 BSP 함수/`xparameters.h`까지 찾아서 호출 대상을 해석합니다.

## Markdown 리포트 구성 (`-f md`)

주석(`//`, `/* */`)과 `#if 0` 블록(및 `#if 1`의 `#else` 쪽)은 분석에서 제외합니다. 그 밖의 `#ifdef` 분기는 양쪽 모두 읽습니다.

0. **한눈에 보기** — 처음 1~2 화면에서 전체 그림을 잡기 위한 요약
   - 0.1 스레드/진입점 구성도: `main()`이 어떤 **순서**로 어떤 스레드·콜백을 시작하는지 (스레드 안에서 다시 만드는 스레드 포함)
   - 0.2 모듈(파일) 간 호출도: 함수 대신 파일 단위로 묶은 호출 관계 (화살표 숫자 = 호출 수)
   - 0.3 진입점별 핵심 흐름: 표준 함수·조건 분기를 뺀 **사용자 함수만**의 번호 매긴 호출 순서 + 그림
   - 0.4 모듈 요약: 파일별 대표 함수
1. **개요** — 프로젝트 형태, 플랫폼(CPU·도메인·XSA), 앱/시스템/HLS 프로젝트, BSP 드라이버 목록, 언어 통계,
   메모리 맵(`lscript.ld`), 하드웨어 주변장치(`xparameters.h`), 코드에서 쓰는 `XPAR_*` 매크로
2. **전체 구조** — 디렉터리 트리(자동 생성 폴더는 접음), 파일별 함수, 함수 호출 관계도(Mermaid, 작은 프로젝트만)
3. **함수 상세** — `main()`부터 **호출하는 함수 → 하위 함수** 순서(위에서 아래로)로 배치
   - 절: `main()`에서 시작 → 각 스레드/콜백(`XScuGic_Connect`, `xTaskCreate` 등으로 등록된 함수)에서 시작 → 진입점에서 도달하지 않는 함수. HLS top 함수(`hls.app`의 `top`, `set_top`)도 진입점으로 취급
   - 절(3.x)과 함수 카드는 모두 접고 펼 수 있음. 절은 기본으로 펼쳐져 있고 함수 카드는 접혀 있어, 모두 접으면 절 제목만 보임
   - 절마다 요약표(들여쓰기 = 호출 깊이), 함수 카드에는 호출 경로(`main › lcd_thread › hmi_init`)와
     "→ 호출하는 함수: 이름 — 한 줄 요약" 목록. 이미 설명한 함수는 `↑ 앞에서 설명`
   - 시그니처, 호출되는 곳, 표준 함수 포함 전체 호출, 전역 변수, 반복문, 소스는 "자세히"에 접힘
   - `-o 폴더` 분할 저장 시 절마다 `files/01_main.md`, `files/02_<스레드>.md` … `files/99_unreached.md`
4. **자료형·매크로·전역 변수** — 전역 변수는 "어떤 함수가 사용하는지"까지 표시

### 함수 한 줄 요약 규칙

외부 서비스 없이 규칙으로 만듭니다 (`analyzer/summary.py`).

1. 함수 위 주석의 첫 문장 (주석 처리된 코드는 제외)
2. 주석이 없으면 이름으로 추정 — `get_local_ip` → "local ip 조회", `uart_buffer_write` → "uart buffer 쓰기",
   `*_thread` → "… 스레드". 함수 상세에 _요약은 이름 기반 추정_ 으로 표시
3. 성격 태그 — `⚡ 스레드`/`⚡ 콜백/핸들러`(등록된 함수), `🔁 상주 루프`(무한 반복), `네트워크`·`파일 I/O`·`메모리 매핑`·
   `동기화`·`시리얼`·`GPIO`(호출하는 함수 기준), `유틸`(짧고 사용자 함수를 호출하지 않음)

## Vitis 처리 방식

| 대상 | 처리 |
|---|---|
| `.metadata`, `RemoteSystemsTempFiles`, `Debug/`, `Release/`, `.Xil` | 탐색 제외 |
| 플랫폼 프로젝트(`platform.spr` 폴더), `libsrc`, `bsp`, `zynq_fsbl`, `export`, `_ide`, HLS `solution*/syn·impl·sim` | **자동 생성 코드**: 통계·상세 분석 제외, 함수/매크로 정의만 색인해 호출 대상 해석에 사용 |
| `<app>/src/` 등 나머지 | 사용자 코드: 전체 분석 |
| `.xsa`, `.bit`, `.elf` | 바이너리 → 건너뜀 (이름만 플랫폼 정보에 표시) |

```
└── reporters/
    ├── text.py              터미널 요약
    └── markdown.py          상세 Markdown 리포트
tests/                       단위 테스트 + Vitis 2020.2 형태 샘플 워크스페이스
```

## 기본 처리 규칙

- 소스 인코딩: UTF-8 → CP949(EUC-KR) 순으로 자동 판별 (한글 주석이 깨지지 않음)
- 루트의 `.gitignore`를 git 규칙대로 적용 (`/`, `**`, `!` 지원). 하위 폴더의 `.gitignore`는 읽지 않음
- 백업·임시 파일(`*.bak`, `*.orig`, `*.old`, `*.tmp`, `*.swp`, `*~`)은 제외
- 호출 대상 분류: 사용자 함수 / 매크로 / BSP·외부 라이브러리 / 표준 C / POSIX·Linux / 외부·미확인

## 한계

컴파일러 없이 정적으로 분석합니다.
- `#ifdef` 분기는 양쪽 모두 읽고, 매크로 전개는 하지 않습니다.
- 함수 포인터 배열/구조체 멤버를 통한 호출은 `[함수 포인터 호출]`로만 표시됩니다.
- 호출 순서는 소스에 적힌 순서 기준이며 실제 런타임 분기 결과는 반영하지 않습니다.
- Lua/Python은 아직 통계·진입점만 지원합니다. 함수 분석은 다음 단계입니다.
